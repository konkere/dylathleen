# First iteration

Starting point: fork main at b1ea479a, bauh 0.10.7. The Qt frontend delegates to SoftwareManager backends. Upstream discovered controllers by scanning the package directory and using deprecated Python loader APIs. The fork explicitly imports four managers. Historical arch and debian modules remain in the source tree and their unit tests still run, but the DEB omits them.

The original Flatpak implementation parsed an interactive transaction listing, used an application-ID-only cache and also assigned installed and target versions from a Flathub background request. These paths could combine data from different commits or versions. The original incident's exact sequence cannot be reconstructed. Deployment and update data now come from Flatpak's tabular output. Metadata enrichment is limited to descriptions, names, icons and categories for installed refs. The preview distinguishes absent metadata and rebuilds in both the package table and confirmation dialog. The targeted installations are the default system and per-user installations. Named installations, pinned transaction previews and exact preflight download sizes remain future work. Related runtimes are resolved by Flatpak at transaction time.

The Debian package installs system-Python entry points, a private application module, desktop entries and a scalable icon. Application state uses the fork's name. Installation needs administrative rights; opening the GUI and enumerating software do not. Snap modifications and some system operations use sudo; Flatpak typically delegates authorization to its system helper. Password validation checks sudo's exit status. Passwords are passed on stdin and remembering a password during the session is off by default. The fork retains optional Timeshift integration. Running the GUI as root is not required.

AppImage catalogues and Web Apps toolchain settings still come from upstream bauh-files. The AppImage backend uses SQLite files, the sqlite3 CLI and x86-64 AppImages. The web backend needs Beautiful Soup and lxml and wraps sites using Nativefier. Remaining desktop checks cover authorization and application launches on Wayland, and the full Web Apps lifecycle. The archive and subprocess changes are targeted fixes, not a complete security review. Audit remaining privileged operations, external downloads, catalogue freshness and upstream toolchain maintenance before a public release.

See packaging/check-distribution for the DEB install, lint, unit and non-root Qt startup checks. packaging/check-flatpak.py creates a private file remote and two tiny test applications, publishes changed commits, verifies the preview, installs updates and checks the resulting inventory. It requires a working local Flatpak user session. No public release or repository is needed to run either test.

## Local verification on 2026-11-20

The same architecture-independent DEB was installed with APT in clean amd64 containers for Ubuntu 22.04, 24.04 and 26.04 and Debian 12 and 13. Each ran 150 unit tests, flake8's syntax/undefined-name checks, desktop-file validation, a non-root offscreen Qt startup through the first inventory refresh and the table/confirmation label checks. The installed CLI and GUI launchers reported the expected help/version. This covers system Python 3.10, 3.11, 3.12, 3.13 and 3.14 with distro PyQt5. A graphical desktop session and interactive authorization were outside these container tests.

On the Ubuntu 22.04 host, Flatpak 1.12.7 supplied the locally installed GIMP 3.2.8 and Plexamp 4.13.2. An isolated fixture remote reproduced the earlier versions and new commits. The controller prepared and executed both upgrades without changing real applications, including when the system installation could not be read. The Snap client read 32 installed records through snapd. The downloaded upstream AppImage archive yielded a SQLite catalogue with 956 entries and the backend found 3dco-plus. GitHub-hosted Actions will first run when the work is published.

In a separate manual check, Konkere confirmed that interactive authorization prompts worked in X11 and completed the install, launch and removal cycle for both Snap and AppImage. Wayland was unavailable for this check. The Web Apps lifecycle remains untested.
