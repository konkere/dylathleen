# Dylath-Leen

A harbor for Linux applications.

[English](README.md) · [История изменений](CHANGELOG.md)

Самостоятельный форк [bauh](https://github.com/vinifmor/bauh) автора Vinícius Moreira под лицензией [Zlib](LICENSE). В нативном интерфейсе PyQt5 доступны Flatpak, Snap, AppImage, программы под управлением [marcosnils/bin](https://github.com/marcosnils/bin) и сторонние DEB из [deb-get](https://github.com/wimpysworld/deb-get).

Соберите пакет командой `./packaging/build-deb`, затем выполните `sudo apt install ./dist/dylathleen_0.6.0~test1-1_all.deb`. Запустите Dylath-Leen из меню или командой `dylathleen` от обычного пользователя. APT устанавливает сам менеджер и его зависимости. Внутри программы транзакции APT ограничены приложениями deb-get и их зависимостями.

Обновите список, выберите приложения и проверьте версии в окне подтверждения. Если Flatpak сообщает ту же версию и новый коммит, интерфейс покажет обновление сборки. Если метаданных недостаточно, целевая версия останется неизвестной. Источник версии — каталог соответствующего репозитория. Параметр `--offline` позволяет посмотреть локальный список, `--settings` открывает настройки, `dylathleen-tray` запускает значок в области уведомлений.

Для Snap нужен работающий snapd, для поиска Flatpak — настроенный репозиторий. Модуль AppImage рассчитан на x86-64. Старые локальные приложения и настройки bauh автоматически не переносятся. Целевые платформы — Ubuntu 22.04/24.04/26.04 и Debian 12/13. [Подробности и ограничения](docs/iteration-1.md).


## Системная служба

DEB включает dylathleend. Служба активируется по D-Bus и завершается после простоя. Общее обновление списка проверяет системные bin и deb-get. При сбое источника интерфейс показывает последние известные данные. Таймер проверяет обновления раз в час. Отключить его можно командой `systemctl disable --now dylathleen-refresh.timer` с правами администратора. [Настройка интервала, токена и системных каталогов](docs/system-service.md)

## bin

Установите [marcosnils/bin](https://github.com/marcosnils/bin/releases) v0.29.4 или новее и добавьте его в `PATH` либо в один из настроенных каталогов bin. Откройте **Действия → Установить из репозитория (bin)** и введите HTTPS-адрес репозитория. Поддерживаются вложения релизов GitHub, Codeberg и GitLab для адресов вида `owner/repo`. По умолчанию выбран последний стабильный релиз. Выберите файл для своей платформы и, если потребуется, программу внутри архива. Контрольные суммы, подписи и исходники отфильтрованы. Для файлов, доступных только в реестре пакетов GitLab или в описании релиза, используйте CLI.

Список автоматически показывает установки текущего пользователя и системные установки bin. Выбранный релиз скачивается от имени пользователя. Системный файл записывает dylathleend после авторизации через Polkit. Закрепление версии доступно в меню строки.

В **Настройках → bin** можно изменить оба каталога. Программа перенесёт файлы, зарегистрированные в соответствующей области, и обновит пути и каталог по умолчанию для CLI. При конфликте или обнаружении подменённого файла перенос этой области останавливается. Изменения двух областей сохраняются независимо. Системный путь должен состоять из каталогов, принадлежащих root, с записью только для владельца. Чтобы вызывать команды по имени после переноса, добавьте новый каталог в `PATH`.

Проверка обновлений выполняется через `bin update --dry-run`. Установка по тегу сохраняет возможность обновления. Для удержания версии используйте **Закрепить версию**. Если `bin` не может однозначно подобрать прежний вариант, для поддерживаемых репозиториев GUI предлагает выбрать файл заново. Для прочих источников, уже зарегистрированных в `bin`, доступны автоматические обновления, которые разрешает штатный CLI. Не изменяйте один реестр одновременно из терминала и Dylath-Leen.


## deb-get

Установите deb-get 0.4.7 отдельно и запустите Dylath-Leen от обычного пользователя. Откройте **Действия → Открыть каталог deb-get** или введите `deb-get` в основном поиске. Для новой установки выполните **Обновить каталог deb-get**. Доступны установка, выборочное и массовое обновление, переустановка, удаление и purge приложений deb-get.

Проверка обновлений пропускает общесистемное обновление индексов APT. Версии APT/PPA помечены как данные из существующих индексов. Перед транзакцией показывается план, а удаление ограничено выбранным пакетом. GitHub-токен берётся из `DEBGET_TOKEN` или приватного файла `~/.config/deb-get/github-token` исходного пользователя.

Через **Управление локальными рецептами deb-get** можно импортировать, редактировать, сравнивать, экспортировать и восстанавливать рецепты в `/etc/deb-get/99-local.d/`. Мастер GitHub/GitLab анализирует релизы и проверяет DEB перед тем, как предложить динамический рецепт. Редактор постоянно показывает предупреждение об исполняемом Bash-коде. Сохранение работает с текстом, а определение версии через deb-get выполняется отдельным действием после подтверждения. [Подробности и чек-лист](docs/deb-get.md)

## Запуск приложений bin и deb-get

Щёлкните правой кнопкой по установленному приложению или откройте меню его строки. Выберите **Настроить запуск**, укажите исполняемый файл, аргументы и режим. В автоматическом режиме Dylath-Leen использует подходящий ярлык и открывает терминал при `Terminal=true`. Если ярлыков несколько, выберите один. Если подходящего ярлыка нет, задайте режим вручную.

Для bin в поле сразу указан путь из реестра. Для deb-get можно выбрать один из обнаруженных исполняемых файлов или ввести собственный путь. Настройки сохраняются между обновлениями и перезапусками. При переносе каталога bin обновляются пути к перенесённым программам. Запуск всегда происходит от текущего пользователя.

В окне **?** для установленных приложений deb-get доступны пути из dpkg, обнаруженные исполняемые файлы, команда с аргументами и путь к ярлыку. Значок глаза раскрывает список, значок копирования переносит значение в буфер обмена.
